# UI 規格

> 狀態：初稿（2026-10-26）。
> 需求以 [`prd.md`](../prd.md) F6 為準；本文件只補 PRD 未訂的呈現細節。

## 0. 範圍與邊界

**本文件管**：頁面結構、卡片在各種狀態下的呈現、互動、文字與格式化、瀏覽器端儲存。

**本文件不管**：數字怎麼算、狀態怎麼判定、排序規則（[`calc.md`](calc.md)）；前端讀取的 JSON 格式（[`data-model.md`](data-model.md) §6）。前端**不重新計算**任何數值，只依 JSON 呈現；唯一的例外是新鮮度，因為它取決於訪客看頁面的當下時間：前端重算新鮮度標示、中斷橫幅，以及因池子轉為過期而改變的排序（UI-FRESH）。排序規則本身仍以 `calc.md` 為唯一定義。

**條文編號**：`UI-<主題>-<序號>`。編號永久不重用。

---

## 1. 基本

- **UI-BASE-1** 純靜態網站：建置產物為 HTML／JS／CSS，執行時只讀取同網域的 `data/latest.json` 與語系檔。除流量統計外不向任何外部網域發出請求（NFR-AC2、NFR-AC8）。
- **UI-BASE-2** 單一頁面，無導覽列。由上到下：頁首 → 搜尋框 → 我的關注 → 市場收益排行 → Dev's Pick → 計算方法說明 → 頁尾（PRD F6）。
- **UI-BASE-3** 頁首：站名、資料更新時間（`generated_at` 轉為訪客當地時區，格式 `YYYY-MM-DD HH:mm`）、一行免責聲明。
- **UI-BASE-4** 流量統計使用 Cloudflare Web Analytics（不使用 cookie）。
- **UI-BASE-5** `latest.json` 載入失敗時，整頁顯示「資料暫時無法載入，請稍後重新整理」，不顯示空的區塊。

## 2. 響應式

- **UI-RWD-1** 斷點：寬度 < 640px 為手機版。手機版不得出現橫向捲動（NFR-AC6），驗證寬度為 360px。
- **UI-RWD-2** 手機版的池子列改為上下堆疊（範例見 §4.2），合約地址以中段省略顯示（`0x55d3…7955`），複製時仍複製完整地址。

## 4. 股票卡片：展開狀態

### 4.1 代幣區

每個代幣一列：鏈、發行商、代號、合約地址（可複製）、區塊瀏覽器連結、狀態標籤（「官方已下架」「暫停交易」為醒目標籤）（F6-AC10）。

| 鏈 | 區塊瀏覽器網址 |
|---|---|
| BSC | `https://bscscan.com/token/{address}` |
| Solana | `https://solscan.io/token/{address}` |
| Robinhood | `https://robinhoodchain.blockscout.com/token/{address}` |

### 4.2 池子區

依費率階梯分組（CALC-RANK-8），每組先列預設池子，其他費率摺疊為「其他費率（N）」，點擊展開（F3-AC1）。組與組之間的順序：預設池子可排名者在前，依淨收益由高到低；不可排名者在後，依 24h 交易量由高到低。

每個池子顯示（F6-AC20）：

```
PancakeSwap V3 · BSC · TSLAB/USDT 0.25%          [前往池子]
發行商 bStock
TVL $2.06M   24h 交易量 $1.36M
全區間 APY 3.1% ↑ 30天 2.5%     池子平均 60.4% ⓘ
淨收益 +1.3%    損耗比 58%
```

- **UI-POOL-1** 股票配股票的池子在第二行加上「另一邊：NVDA」，並可點擊捲到該卡片（F3-AC2）。發行商與另一邊的股票一律由 `sides` 判斷，不解析 `pair_label`。
- **UI-POOL-2** V2 池只顯示一個 APY，不顯示「池子平均」（F6-AC8）。
- **UI-POOL-3** 近似值在數字前加 `≈`（例：`全區間 APY ≈3.1%`），點擊顯示「含回補期間的估算值，系統運行滿 30 天後自動改為實測值」（PRD F6）。
- **UI-POOL-4** 「前往池子」連結到 DEX 的池子頁面（`pool_url`，見 §8）。
- **UI-POOL-5** 每個展開的卡片底部有一行小字免責聲明，連到計算方法說明。

### 4.3 池子狀態的呈現

| 狀態 | 呈現 |
|---|---|
| 官方已下架、暫停交易 | 池子列上方加醒目標籤；數字照常顯示 |
| 錯誤、無法計算 | APY、淨收益、損耗比顯示「無法計算」；TVL、交易量照常顯示（F2-AC20） |
| 數據過期 | 整列灰掉，標示「數據過期」 |
| 資料不足 | APY、淨收益、損耗比的位置顯示「資料僅 N 天」（這些值未計算，CALC-AGG-3）；TVL、交易量照常顯示 |
| 數據延遲 | 黃色標示「數據 N 小時前」 |
| 異常 | 標記圖示，點擊說明「此池 APY 明顯高於同一檔股票的其他池子，請自行確認」 |
| 收益波動大 | 標記圖示，點擊說明「即使不看最好和最差的一天，最近 7 天的每日收益仍相差 {thresholds.apy_spread_ratio_flag} 倍以上，7 天 APY 可能不代表典型的一天」 |

- **UI-STATE-1** 有次要狀態時，點擊主要狀態標籤可看到其餘狀態（F2-AC19）。

## 5. 文字說明

- **UI-TEXT-1** 損耗比的白話說明（點擊或滑過）：
  - `fee_loss_ratio < 1`：「無常損失約吃掉 {fee_loss_ratio} 的手續費。股價波動再大 {headroom}，就會開始虧損。」
  - `fee_loss_ratio ≥ 1`：「目前手續費不足以補償股價波動的風險，預期會虧損。」
- **UI-TEXT-2** 池子平均 APY 的 ⓘ：「池子平均是所有 LP 的平均收益。這個池子的流動性大多集中在現價附近的窄區間，由積極調整區間的做市商賺走大部分手續費；全區間的被動 LP 實際約能拿到 {apy_7d}。」
- **UI-TEXT-3** 「我的關注」為空時：「點 ☆ 把股票加到這裡」（F6-AC16）。
- **UI-TEXT-4** 計算方法說明必須涵蓋以下項目，每項一個小節（F6-AC19）：
  1. 淨收益的計算方式（全區間 APY、7 天中位數、σ²/8）
  2. 哪些池子被過濾及原因（TVL 下限、報價資產分級、V4／Infinity 池已排除、各種狀態）
  3. 收錄池子 24h 交易量的排除範圍
  4. 已知限制：不含挖礦獎勵；回補期間的 TVL 與集中流動性池的 L 為近似值；波動率取自美股股價，未涵蓋週末與流動性差時代幣自身的價格偏離，對流動性差的池子可能低估無常損失
  5. 本站評估的是被動 LP，所以數字比 DEX 頁面低
  6. 當 LP 是做空波動率
  7. 排名相近不代表有高低之分
  8. 手續費損耗比的含義

  文案可改寫自參考專案 `MODEL.md`。所有文字放在語系檔。

## 6. 互動

- **UI-NAV-1** **分批顯示**：市場收益排行每批 20 檔。「顯示更多（還有 M 檔）」按鈕在全部顯示後消失（F6-AC11）。「我的關注」與 Dev's Pick 不分批。
- **UI-NAV-2** **搜尋**（F6-AC12～F6-AC14）：輸入時即時篩選（150ms 防抖），範圍為 JSON 中所有卡片（含情況 C）。比對規則：
  - 代號：不分大小寫的**前綴比對**，對象為卡片代號與所有代幣代號（輸入 `NVDA` 找到 `NVDAB`、`NVDAx`）。
  - 名稱：不分大小寫的子字串比對。
  - 合約地址：輸入以 `0x` 開頭時，不分大小寫的完整比對；其他長度 32～44 的 base58 字串，區分大小寫的完整比對。找不到時顯示「找不到符合的股票」。
  - 搜尋中時，三個區塊改為單一的「搜尋結果」清單，依 CALC-RANK-7 的預設規則排序；清空搜尋框即恢復。
- **UI-NAV-3** **錨點**：展開卡片時網址改為 `#{slug}`（使用 `history.replaceState`，不新增瀏覽紀錄）；收合時移除錨點。開啟帶錨點的網址時，捲到該卡片並展開；卡片在排行榜尚未顯示的批次中時，先載入到該批次（F6-AC15）。
- **UI-NAV-4** **我的關注**：☆ 切換加入或移除，立即生效。排序切換鈕「依交易量／依淨收益」（F6-AC22）。

## 7. 瀏覽器端儲存

- **UI-STORE-1** 關注清單存於 `localStorage`，鍵 `lpa.watchlist.v1`，值為 `stock_id` 的 JSON 陣列。加入或移除不送出任何網路請求（F6-AC17）。
- **UI-STORE-2** `localStorage` 讀寫失敗（私密瀏覽、被封鎖）時，關注功能在本次瀏覽中仍可用（存在記憶體），並在「我的關注」顯示「此瀏覽器無法保存關注清單」。
- **UI-STORE-3** 清單中的 `stock_id` 在 JSON 中找不到時（例如被人工排除）不顯示，但不從清單刪除。

## 8. 外部連結

- **UI-LINK-1** 「前往池子」的 `pool_url` 由後端依 DEX 對照表（[`sources.md`](sources.md) §4）的池子頁面網址格式產生，與該 DEX 能否計算無關（F6-AC10）。網址格式只記在 DEX 對照表中，本文件不另列。展示的池子必定來自已啟用的 DEX，而啟用的前提之一是網址格式已實測（SRC-DEX-4），因此每個展示的池子都有 DEX 頁面連結，不需要替代連結。
- **UI-LINK-2** 所有外部連結以新分頁開啟，加上 `rel="noopener noreferrer"`。

## 9. 新鮮度與中斷橫幅

- **UI-FRESH-1** 前端使用的門檻一律讀 `latest.json` 的 `thresholds`，不在前端另設常數，避免與後端設定不同步。
- **UI-FRESH-2** 頁面開啟期間，每 10 分鐘重新抓取 `latest.json`；抓取失敗時保留目前資料，下次再試。重新抓取後保留展開狀態、搜尋內容與捲動位置。
- **UI-FRESH-3** 每個池子的新鮮度標示由前端以訪客當下時間重算：`now − last_complete_snapshot_at` 依 `thresholds` 分為正常、數據延遲（「數據 N 小時前」，N 無條件捨去到整數小時）、數據過期（灰掉）；`last_complete_snapshot_at` 為 `null` 時一律為數據過期（CALC-STATE 表）。即使 JSON 匯出時該池子還是正常，訪客晚開頁面時仍會看到正確的標示。
- **UI-FRESH-4** **中斷橫幅**：`now − last_successful_run_at > thresholds.pipeline_banner_hours` 時，頁面頂端顯示「資料更新中斷，以下為 {last_successful_run_at} 的數據」，下方內容照常顯示（F6-AC18）。
- **UI-FRESH-5** **過期後重新排序**：前端依 UI-FRESH-3 算出某池子為數據過期、而 JSON 中它不是時（只發生在後端停擺、JSON 未再更新的期間），前端把「數據過期」**加入**該池子的狀態集合（JSON 的 `status.primary` 與 `status.secondary`），移除「數據延遲」提示，再依 PRD 狀態表由上而下重新選出主要狀態（F2-AC19）：原本為「官方已下架」「暫停交易」「錯誤」「無法計算」的池子主要狀態不變，「數據過期」成為次要狀態；原本沒有排除類狀態或主要狀態為「資料不足」的池子，主要狀態變為「數據過期」。接著依 [`calc.md`](calc.md) CALC-RANK-2、CALC-RANK-4～CALC-RANK-8 重新選取最佳淨收益、卡片分類、情況 B 的主要原因與排行順序。例：後端停擺超過 24 小時後，原本為情況 A 的卡片轉為情況 B，排到可排名卡片之後，與 F6-AC5 一致。
- **UI-FRESH-6** 前端排序實作與後端共用一組測試案例（[`test.md`](test.md) TEST-DATA-7）：沒有任何池子被前端改為過期時，前端的結果必須與 JSON 完全相同。
- **UI-FRESH-7** **本地計時器**：新鮮度的轉換不等重新抓取 JSON。前端算出所有池子中「下一個跨過延遲或過期門檻」的時間點與橫幅門檻的時間點，在最早的那一刻觸發重算（UI-FRESH-3～UI-FRESH-5），之後再排下一個。分頁從背景切回前景時（`visibilitychange`）立即重算一次，因為瀏覽器會延後背景分頁的計時器。

## 10. 語系與格式化

- **UI-I18N-1** 所有顯示文字放在 `locales/zh-TW.json`，元件中不得寫死顯示文字（NFR-AC7）。語系鍵以功能分組（例：`card.volume24h`、`status.stale`、`methodology.passiveLp.title`）。
- **UI-I18N-2** 數字與日期以 `Intl` API 依語系格式化。百分比依 CALC-DISP-1；金額 ≥ 10 億顯示 `$1.23B`，≥ 100 萬顯示 `$2.06M`，≥ 1,000 顯示 `$45.6K`，其餘顯示整數。
- **UI-I18N-3** 損耗比顏色依 CALC-DISP-2；顏色之外另有文字標示數值，不單靠顏色傳達資訊。
