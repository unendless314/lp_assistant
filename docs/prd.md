## 1. 背景

參考專案 [`bstocks-lp-assistant`](../reference/SOURCE.md) 用期權視角評估代幣化股票 LP 的風險調整收益，數學模型完善，但有三個限制：

1. 只看 BSC 上的 bStock，看不到 Solana 等其他鏈與其他發行商。
2. 無法比較同一檔股票在不同鏈、不同池子的收益。
3. 池子資料依賴 `baw`，必須登入錢包才能運作。

## 2. 目標

做一個**唯讀**的代幣化股票 LP 比較工具：對同一檔美股，列出它在各鏈、各發行商、各費率階梯的 LP 池子，用一致的方法比較風險調整後的收益，並提供資金配比建議。

## 3. 使用者與使用情境

- **定位**：個人工具，公開唯讀。不做帳號、不做登入，任何人都能瀏覽。
- **主要使用者**：開發者本人。
- **其他訪客**：可以瀏覽、在自己的瀏覽器裡建立關注清單。
- **使用情境**：打開網頁，看自己關注的股票目前哪條鏈、哪個池子的淨收益最好；順便看市場上淨收益最高的是哪些股票。
- 若之後確認有流量，再評估是否升級為正式產品（見 §9）。

**與參考專案的定位差異**

| | 參考專案 | 本專案 |
|---|---|---|
| 定位 | Agent 互動工具 | 資料匯集站 |
| 運作方式 | 使用者提問時即時抓取、計算 | 排程定期抓取、計算並儲存 |
| 介面 | Claude 對話、命令列 | 訪客只有網頁；伺服器本機另有唯讀的命令列資料介面，供開發者與同機 agent 使用（見 §9） |
| 與錢包的關係 | 讀取持倉、交給錢包執行 | 完全不碰 |

因此只移植參考專案的數學模型與過濾規則，不移植其互動流程。未來需要依使用者輸入計算的功能（資金配比、區間試算），須在瀏覽器端計算或事先算好，因為伺服器只提供靜態檔案。

## 4. 功能需求

> **驗收條件**：每個功能最後的「驗收條件」以編號列出可驗證的行為（例如 `F2-AC3`），測試規格以編號引用，確保每條需求都有測試、每個測試都對應需求。驗收條件只寫行為，不寫門檻數字（門檻於計算規格訂定）。公式與演算法的正確性（例如 Yang-Zhang 波動率、無常損失）不寫在本文件，由計算規格以編號條文（例如 `CALC-3`）訂定，測試規格同時引用 PRD 驗收條件與計算規格條文。
> 驗收條件 2026-10-25 起草，2026-10-26 經外部交叉審查與開發者審閱後定案。
>
> **「日」的定義**：本文件中的「當日」「每日」「N 天」一律指 UTC 日，各資料來源的時間統一換算成 UTC 後再切日，不讓各來源各自切日；網頁上顯示的時間由瀏覽器轉為訪客的當地時區。細節見計算規格。

### F1. 代幣與池子收錄
- 收錄 bStock（BSC）、xStocks（Solana、BSC）與 Robinhood 股票代幣（Robinhood Chain）。**代幣清單一律取自發行商的官方來源**，不使用第三方整理的清單：

  | 發行商 | 官方來源 | 說明 |
  |---|---|---|
  | bStock | 幣安股票代幣清單（`type=3`） | 發行商 BTech Holdings 為幣安集團關聯企業，發行與上架皆經由幣安 |
  | xStocks | xStocks 官方公開 API（免登入） | 發行商 Backed 自己的清單；不再使用幣安轉列的 xStocks 清單 |
  | Robinhood | Robinhood 官方公開 API（免登入） | — |

  實測見 [`research/2026-10-25-token-sources.md`](research/2026-10-25-token-sources.md)。

- **只收錄官方清單上的代幣**（以合約地址比對），第三方發行的同名代幣、第三方槓桿代幣（如 `AAPLx3L`）一律不收錄。
- **只收錄標的為美股的代幣**：標的在美國交易所掛牌（NYSE、Nasdaq、NYSE Arca、Cboe BZX、NYSE American），含 ADR 與在美上市的外國公司，不看公司國籍。例如 `BABAx`（NYSE ADR）、`PDDx`、`TSMx` 收錄；`TCENTx`（港交所）不收錄。理由：波動率取自美股股價（見 F2），非美股的交易時段、幣別、股價代號都不同。非美股列為第二版候選（見 §9）。判斷規則於數據規格中訂定（實測 xStocks 官方資料有部分代幣缺少交易所欄位，需備援判斷）。
- **排除槓桿與反向 ETF**（例如 `TSLLx`、`SQQQx`、`TMFx`、`UVXYx`），即使是官方發行的代幣。理由：每日再平衡讓價格路徑偏離，無常損失公式不適用。僅靠名稱關鍵字判斷會誤判（例如 `RBCx` RBC Bearings、`BLSHx` Bullish），判斷規則於數據規格中訂定。
- EVM 鏈上同一檔代幣可能有多個官方地址（xStocks 的主地址與 `wrapperAddressV2`，實測幣安在 BSC 上列的 `wTCENTx` 即為包裝地址），皆視為官方地址，兩者的池子都收錄。
- 以美股標的對齊不同鏈、不同發行商的代幣（`TSLAB`、`TSLAx`、Robinhood 的 `TSLA`）。有 ISIN 時優先用 ISIN 對齊，避免同代號不同股票類別混淆。
- 同一檔股票在同一條鏈上可能有多個發行商，兩者都要列出。
- **資產登記表**：系統自己維護一份已收錄代幣的登記表，網頁一律依登記表呈現股票卡片，不因當下抓不到數據而消失。此規則的用意是**斷線時卡片不消失**，不是把沒有池子的股票全部列進排行榜：目前沒有任何收錄池子的股票不進「市場收益排行」，但可被搜尋、加入關注（見 F6）。
  - 官方清單只能**新增**登記，不能刪除。新代幣出現在官方清單即自動收錄，不需人工核准。
  - 代幣從官方清單消失時只改狀態：連續 N 天未出現才標為「官方已下架」（N 由設定檔決定），避免官方 API 單日異常造成誤判。
    - 只有**成功取得、並通過完整性檢查**的官方清單才算一次有效更新（分頁完整、格式與必要欄位正確；檢查項目見數據規格）。抓取失敗或未通過檢查時，沿用上次有效的清單，**不累計**未出現天數，否則 API 故障幾天就會讓全部代幣被誤判下架。
  - 「官方已下架」的代幣照常顯示池子的 TVL、交易量、APY，加上醒目標籤，**不參與排名**。理由：下架、破產屬於跳空事件，代幣也可能因停止贖回而與股價脫鉤，模型的波動率與無常損失估算不再適用。
  - 官方來源標示**暫停交易或暫停發行／贖回**的代幣（例如 xStocks 的 `isTradingHalted`），比照「官方已下架」處理：照常顯示、加標籤、不參與排名，恢復後自動解除。理由相同：可能與股價脫鉤。
  - 人工設定檔只做例外調整（以合約地址排除特定代幣、加註記），系統沒有它也能運作。
  - 系統運作必需的內建資料（例如 F5 的核心報價資產地址表）**不屬於**人工設定檔，隨程式碼一起維護，不可移除。
  - 每次登記表有變動（新增、消失、恢復），記錄下來供開發者查看。

#### F1 驗收條件
- **F1-AC1** 代幣清單只取自 bStock、xStocks、Robinhood 三個官方來源；系統不呼叫任何第三方代幣清單（例如幣安轉列的 xStocks 清單）。
- **F1-AC2** 合約地址不在官方清單上的代幣，即使代號相同，也不出現在任何卡片或搜尋結果中。
- **F1-AC3** 標的在美國交易所掛牌的代幣被收錄，在非美國交易所掛牌的不被收錄（例：`BABAx` 收錄，`TCENTx` 不收錄）。
- **F1-AC4** 官方資料缺少交易所欄位時，仍能正確判斷是否為美股（例：`PDDx` 收錄）。
- **F1-AC5** 槓桿與反向 ETF 不被收錄（例：`TSLLx`、`SQQQx`）；名稱含類似字樣的一般股票仍被收錄（例：`RBCx`、`BLSHx`）。
- **F1-AC6** EVM 鏈上同一代幣的主地址與包裝地址，其池子都出現在同一張股票卡片中。
- **F1-AC7** 同一標的不同發行商、不同鏈的代幣出現在同一張股票卡片中（例：`TSLAB`、`TSLAx`、Robinhood 的 `TSLA`）。
- **F1-AC8** 官方清單新增的代幣，在下一次清單更新後自動收錄，不需人工操作。
- **F1-AC9** 代幣從官方清單消失未滿 N 天，狀態不變；連續 N 天未出現，標為「官方已下架」；重新出現時自動恢復。
- **F1-AC10** 代幣從官方清單消失後，不會從登記表刪除。
- **F1-AC11** 官方標示暫停交易、暫停發行或暫停贖回的代幣標為「暫停交易」，官方解除後自動恢復。
- **F1-AC12** 移除人工設定檔後，系統仍能完成清單更新、計算與輸出（內建的核心報價資產地址表不屬於人工設定檔）。
- **F1-AC13** 登記表的每次新增、消失、恢復都留有紀錄（時間、代幣、變動類型）。
- **F1-AC14** 官方清單抓取失敗或未通過完整性檢查（例如分頁不完整、缺少必要欄位）的日子，不計入任何代幣的未出現天數；即使連續 N 天以上失敗，也沒有代幣被標為「官方已下架」。
- **F1-AC15** 有 ISIN 的代幣依 ISIN 歸到同一張股票卡片：ISIN 相同者合併（不論鏈、發行商、代號寫法），ISIN 不同者即使代號相同也不合併。

### F2. 收益與風險評估
- 沿用參考專案的量化方法：Yang-Zhang 波動率、相對波動率（非穩定幣配對）、損益平衡波動率與 Richness（`vol_ratio`）。
  - 參考專案的集中流動性區間與存活機率模型**第一版不做**，與區間試算一起延後（見 §3.5）：本站的 APY 定義為全區間被動 LP，第一版沒有任何數字用到區間模型。
- **波動率資料來源：美股股價（yfinance 日 K 線），三條鏈統一**，不使用參考專案的幣安 DEX K 線。
  - 理由：同一檔股票在各鏈的 σ 相同，跨鏈淨收益的差異只反映手續費收益，比較結果不混入資料源差異；幣安 K 線很可能不涵蓋 Robinhood Chain。
  - 非穩定幣配對（股票 / WETH、WBNB、SOL）的報價資產價格同樣取自 yfinance（例如 `ETH-USD`）。相對波動率**只用兩邊都有資料的日子對齊**（即美股交易日），週末缺口為可接受的取捨。
  - 股票代號需轉換成 Yahoo 格式（例如 `BRK.B` → `BRK-B`）。標的沒有公開股價的代幣，標示「無法計算」。
- **過濾與標記規則**（參考專案的三條規則，依本專案的 APY 定義調整；門檻於計算規格中訂定，狀態的顯示與排名規則以下方「池子狀態一覽」為準）：
  - **TVL 下限**：低於下限的池子不收錄。以**實際 TVL** 判斷，不用全區間等價資金（後者只用於計算收益率）。理由有二：(a) 小池子的價格與交易量容易被操縱或刷量，數據不可靠；(b) V2 池放入資金後收益率會被自己稀釋（例如 TVL 7 萬的池子放入 7 萬，收益率約減半）。集中流動性池的稀釋是相對全區間等價資金計算，影響遠小於 V2 池；完整的稀釋模型屬於延後的 F4。
  - **錯誤狀態**（原「異常費率」）：系統確定數據不可信時，例如鏈上讀到的費率無法解析或超出合理範圍，該池子進入錯誤狀態。
  - **異常標記**（原「同標的 APY 離群值」）：APY 明顯偏離同標的其他池子時**只標記、不排除**，照常顯示與排名，由使用者自行判斷。理由：全區間定義、7 天中位數、TVL 下限已處理原本要擋的虛高；真的表現較好的池子（例如費率恰好合適）也會偏離，排除會誤殺。
  - 原則：**系統確定是錯的才排除；不確定就呈現，並告知使用者。**
- **排名用的收益**：每日 APY 的 **7 天中位數**，用中位數排除單日暴衝（例如大單造成的單日高 APY）。中位數代表「典型一天」的收益，比平均更能預估現在投入後可持續的收益；單日大單無法預期，也可能是刻意刷量。
- **30 天中位數**：只用於顯示，與 7 天對照看出收益趨勢，不參與排名（顯示方式見 F6）。歷史資料不足 30 天時顯示「—」，不用不足的資料硬算。
- **7 天與 30 天一律由本系統自行計算**，不使用資料源現成的值（例如 DefiLlama 的 `apyMean30d`）：它只涵蓋 Solana，BSC、Robinhood 仍須自算，混用反而多一條路徑；且其為平均而非中位數、定義無法驗證。資料源的值只用於對照檢查，差距過大時記錄給開發者檢查，不對使用者標示（資料源報的多為池子平均 APY，對集中流動性池本來就會與本站相差很大，應與本站的池子平均 APY 對照）。
- **APY 穩定度另外標示，不納入排名**：以變異係數（標準差 ÷ 平均）在卡片上標示「收益波動大」，門檻於計算規格中訂定。不做折價：7 天只有 7 個資料點，折價係數沒有理論依據，排名卻會對它很敏感。長期穩定度指標待歷史快照累積後再做，見 §9。
- **跨池比較必須用同一套 APY 算法**，不能直接混用各資料源自己報的 APY。
- **APY 的定義：全區間 LP 能分到的手續費收益**，所有池子共用這個定義。本站評估的是**被動、全區間**的 LP，不評估積極調整區間的做市策略。
  - 每日 APY = 當日 LP 實得手續費 ÷ 當日平均的全區間等價資金 × 365。
  - V2 池：全區間等價資金 = TVL（所有流動性都是全區間）。
  - 集中流動性池（V3 / CLMM）：全區間等價資金 = 2 × L × √P，L（目前在現價、正在賺手續費的流動性）與 √P 從鏈上讀取。L 隨時變動（實測同一池子一小時內相差近一倍），須在每次快照讀取，取當日平均。
  - 理由：「交易量 × 費率 ÷ TVL」對集中流動性池是池子平均，被集中在窄區間的做市商撐高。實測 28 個池子高估 5～101 倍，全區間淨收益只有 −5.0%～+1.6%。見 [`research/2026-10-24-clmm-active-liquidity.md`](research/2026-10-24-clmm-active-liquidity.md)。
  - 讀不到 L 的集中流動性池（例如 Solana 的 Byreal、Meteora DLMM）標示「無法計算」，不參與排名，**不退回**「交易量 × 費率 ÷ TVL」，以免高估 10 倍以上的數字混入排名。
  - 實測顯示，即使依參考專案的區間模型為被動持有一年選擇最佳區間（存活機率 ≥ 60%），淨收益也幾乎不變；以全區間為準排序，對集中流動性池並不吃虧。
- **APY 必須用 LP 實際分到的費率，不是池子收的費率**（高風險點）：各 DEX 的協議會抽走一部分手續費，比例因 DEX 而異，同一 DEX 也可能因費率階梯而不同。實測鏈上設定：

  | DEX | LP 實得比例 | 來源 |
  |---|---|---|
  | PancakeSwap V3 | 67%（0.01% 池）～68%（0.25%、1% 池） | 鏈上 `slot0().feeProtocol` |
  | Uniswap V3（BSC、Robinhood）、Sushi V3 | 75%（0.05% 池）、83%（0.3%、1% 池） | 鏈上 `slot0().feeProtocol` |
  | Raydium CLMM | 84% | 鏈上 `AmmConfig` |
  | Orca Whirlpool | 87% | 鏈上池子帳戶 |
  | PancakeSwap V2 | 約 68%（0.25% 中的 0.17%） | 依官方文件，**未實測** |
  | Ramses V3 | 未知（設定值編碼與 Uniswap 不同） | **待查證** |

  比例須從鏈上讀取（可隨治理投票改變），讀不到或格式未知時標示「無法計算」。
- **歷史資料不足的池子**：可用的歷史資料少於 7 天時，標示「資料僅 N 天」，**不參與「最佳淨收益」的選取與排名**，但仍列在展開的卡片中。
- **回補資料算入歷史資料**：系統上線或發現新池子時，從 GeckoTerminal 回補過去的日交易量，讓排行榜第一天就能運作。回補日的分母（TVL、L）只有現值可用，以現值近似，視為系統初始運行的暫存狀態；本系統快照累積後自動改用實測值（7 天中位數滿 7 天、30 天中位數滿 30 天）。含近似值的數字以 `≈` 標示（見 F6）。
- **排除 V4 架構的池子（所有鏈）**：Uniswap V4 與 PancakeSwap Infinity（含 CLMM 與 Bin 池）一律不收錄、不顯示、不計算。這類池子可掛載 hook（池子建立者自訂的合約），可能未經審計，且公開資料源無法得知池子掛載了哪個 hook。此規則沿用參考專案的 V4 封鎖原則；除非開發者明確同意，否則不開發 V4 相關功能。計算方法說明中須註明已排除這兩類池子。
- **只展示已啟用 DEX 的池子**：系統內建一份 DEX 對照表，每個 DEX 須同時完成兩項確認才標為「啟用」：(a) **協議審查**：人工確認該 DEX 的協議架構不是 V4／Infinity 型（沒有可由池子建立者掛載的 hook 合約），並記下審查依據與日期；(b) **網址實測**：池子頁面網址格式已用真實池子開啟確認。只有已啟用 DEX 的池子會出現在卡片、搜尋、交易量加總與排名中；不在表上或尚未啟用的 DEX，池子照常保存資料並記錄給開發者，但不展示。理由：未經審查的 DEX 可能是未被名稱規則辨識出的 V4 型協議，展示它等於把使用者導向未經檢視的合約；協議審查負責安全，網址實測負責讓每個展示的池子都有 DEX 頁面連結（F6-AC10）。此規則是「不確定就呈現」原則的例外：該原則針對的是已審查協議的數據，不及於未經審查的協議本身。
  - 已啟用的 DEX 是否能計算 APY 是另一回事：能讀取 L 與 LP 實得費率者照常計算；不能者（例如 Byreal、Meteora DLMM）或尚待查證者（例如 Ramses V3）仍依本節規則展示並標示「無法計算」。
- **費率一律從鏈上讀取，不採用池名中的費率**（高風險點）：實測發現 GeckoTerminal 池名寫的費率可能與鏈上實際費率不符（Ramses `NVDA / USDG` 池名為 0.05%，鏈上 `fee()` 為 0.01%），且 Solana 的池名完全不含費率。費率錯誤會讓 APY 直接偏差數倍。池名費率只可用於對照，兩者不符時以鏈上為準並記錄。見 [`research/2026-10-24-clmm-active-liquidity.md`](research/2026-10-24-clmm-active-liquidity.md) §4。
- **費率無法取得的池子**（例如動態費率池）：無法用一致的公式估算 APY，標示「無法計算」，不參與排名。
- **數據過期的池子**：距最後一次成功更新超過 24 小時，不參與排名（顯示方式見 F6）。
  - 「最後成功更新」指池子最後一次取得**完整快照**（計算所需的欄位都已取得）的時間；從未取得完整快照的池子視為數據過期。
  - 日交易量（APY 的分子）另有自己的同步進度：落後超過約一天（門檻見計算規格）同樣視為數據過期，因為 APY 已不再反映近況。
- **手續費損耗比**：無常損失 ÷ APY，即「手續費收入被無常損失吃掉的比例」。對應參考專案的 Richness，數值為其平方（定義見計算規格）。
  - 100% 即損益兩平線：低於 100% 有賺，高於 100% 虧損，使用者不需記門檻。
  - 前端不使用 Rich / Fair / Cheap 等期權術語，改依數值上色：低於 25% 綠色、25% 以上未滿 100% 黃色、100% 以上紅色（剛好 100% 即淨收益為零，歸紅色）。
  - 點擊或滑過時顯示白話說明，例如「無常損失約吃掉 59% 的手續費。股價波動再大 30%，就會開始虧損。」前句說明現況，後句說明容錯空間。
  - **程式變數不可混用**：計算層沿用參考專案的 `vol_ratio`（= Richness），前端顯示用另一個變數 `fee_loss_ratio`（= `vol_ratio`²）。直接拿 `vol_ratio` 顯示會得到錯誤但看似合理的數字（例如 77% 而非 59%），難以察覺。
- **排名只用淨收益，手續費損耗比不作為門檻**：只顯示，不過濾任何池子。產品導向是呈現全貌、由使用者自行判斷，不主觀屏蔽。
  - 在全區間無常損失公式下，損耗比 ≥ 100% 與淨收益 ≤ 0 在數學上等價，這類池子會自然排在最後，不需額外規則。
  - 淨收益與損耗比回答不同問題：淨收益是「預期賺多少」，損耗比是「風險吃掉多少、波動率估錯時還有多少緩衝」，兩者排序可能相反（例如高 APY 高波動的池子淨收益較高，但損耗比也較高）。

#### F2 驗收條件

**波動率與過濾**
- **F2-AC1** 同一檔股票的穩定幣配對池，不論在哪條鏈、哪種穩定幣，使用相同的 σ（股票本身的波動率）。非穩定幣配對依報價資產的標的各自計算相對波動率：標的相同者（例如不同鏈上的 WETH 都對應 ETH）使用相同的值，標的不同者（例如 WETH 與 WBNB）分開計算。
- **F2-AC2** 非穩定幣配對的相對波動率只使用兩邊都有股價的日子。
- **F2-AC3** 實際 TVL 低於下限的池子不出現在任何卡片中，即使其全區間等價資金高於下限。

**APY**
- **F2-AC4** V2 池的每日全區間 APY 等於「當日交易量 × LP 實得費率 ÷ 當日各次快照的平均 TVL × 365」，不使用單一時點的 TVL（回補日的分母見 F2-AC11）。
- **F2-AC5** 集中流動性池的每日 APY 分母使用當日各次快照的 L 換算後的平均，不使用 TVL。
- **F2-AC6** 讀不到 L 的集中流動性池為「無法計算」，不顯示全區間 APY 與淨收益的數字，也不以「交易量 × 費率 ÷ TVL」代替。
- **F2-AC7** 計算一律使用鏈上讀取的費率；池名費率與鏈上不符時，使用鏈上值並留下紀錄。
- **F2-AC8** 讀不到費率或 LP 實得費率比例的池子為「無法計算」。
- **F2-AC9** 排名使用最近 7 天日 APY 的中位數。例：7 天中有 1 天的 APY 是其他天的 10 倍，排名用的值仍等於中位數。
- **F2-AC10** 歷史資料不足 30 天時，30 天中位數顯示「—」。
- **F2-AC11** 回補資料計入歷史天數；計算區間含回補日的數值帶 `≈`，區間內全部為本系統實測資料後 `≈` 自動消失。
- **F2-AC12** 資料源自己報的 APY（例如 DefiLlama）不參與任何排名計算；與本站差距過大時只寫入開發者紀錄，不顯示給使用者。
- **F2-AC13** Uniswap V4 與 PancakeSwap Infinity 池不出現在任何卡片、搜尋結果或交易量加總中。

**手續費損耗比**
- **F2-AC14** 損耗比顯示值為 `vol_ratio` 的平方。例：`vol_ratio` = 0.77 時顯示 59%，不是 77%。
- **F2-AC15** 損耗比低於 25% 顯示綠色，25% 以上未滿 100% 黃色，100% 以上紅色。例：剛好 25% 為黃色，剛好 100% 為紅色。
- **F2-AC16** 損耗比不影響任何池子是否顯示或是否參與排名。

**池子狀態**
- **F2-AC17** 排除類狀態的池子不參與最佳淨收益的選取，但仍列在展開的卡片中，並計入卡片的 24h 交易量。
- **F2-AC18** 提示類狀態（數據延遲、異常、收益波動大）的池子照常參與排名，排名不因標記而改變。
- **F2-AC19** 池子同時符合多種狀態時，主要標示為狀態表中由上而下最先符合者，其餘可在點擊說明中看到。
- **F2-AC20** 「錯誤」與「無法計算」對使用者顯示相同字樣，系統紀錄中可區分兩者並保留原因代碼。
- **F2-AC21** 數據距最後成功更新未滿 2 小時的池子不帶新鮮度標記；2 小時以上、24 小時以內標示「數據延遲」；超過 24 小時標示「數據過期」並不參與排名。從未成功更新的池子，以及日交易量同步落後超過門檻的池子，同樣為「數據過期」。
- **F2-AC22** σ 超過 7 天未更新時，相關池子轉為「無法計算」；7 天內沿用上次的 σ。
- **F2-AC23** 所有池子（V2 與集中流動性池）的 APY 都使用 LP 實得費率，不使用池子收取的費率。
- **F2-AC24** 鏈上讀到的費率無法解析或超出合理範圍時，池子為「錯誤」狀態，不是「無法計算」。
- **F2-AC25** APY 偏離同標的其他池子超過門檻時標示「異常」，未超過時不標示。
- **F2-AC26** 7 天日 APY 的變異係數超過門檻時標示「收益波動大」，未超過時不標示。
- **F2-AC27** 不在 DEX 對照表上、或在表上但尚未啟用（協議審查或網址實測未完成）的 DEX，其池子不出現在任何卡片、搜尋結果、交易量加總或排名中，但資料仍保存在資料庫，並寫入開發者紀錄；已啟用但不能計算的 DEX 的池子照常展示，標示「無法計算」。

### F3. 比較視圖
- 跨鏈：同一檔股票在各鏈的收益、TVL、交易量。
- 跨發行商：同一檔股票的不同發行商代幣。
- 跨費率階梯：同一 DEX 同一交易對的不同費率池，預設只顯示一個，可展開查看其他。預設顯示的池子：可參與排名的池子中淨收益最高者；全部屬於排除類狀態時，取 24h 交易量最高者（與 F6 情況 B 的排序一致）。
- **股票配股票的池子**（例如 `SPY/NVDA`）同時列在兩檔股票的卡片上，資料只有一份，兩邊顯示的數字相同：
  - 兩張卡片都可選它為「最佳淨收益」。
  - 兩張卡片的 24h 交易量都計入它的交易量（網站沒有跨卡片加總的數字，不會重複計算）。
  - 展開時標示另一邊的股票。

#### F3 驗收條件
- **F3-AC1** 同一 DEX 同一交易對有多個費率池時，預設只顯示一個，其他可展開查看。預設顯示可參與排名的池子中淨收益最高者；全部屬於排除類狀態時，顯示 24h 交易量最高者。
- **F3-AC2** 股票配股票的池子同時出現在兩檔股票的卡片中，兩邊顯示的數字相同，並標示另一邊的股票。
- **F3-AC3** 股票配股票的池子可被任一張卡片選為最佳淨收益。
- **F3-AC4** 股票配股票的池子的交易量計入兩張卡片的 24h 交易量。

### F5. 報價資產分級與自選報價代幣
池子依「另一邊的資產」分三級：

| 級別 | 內容 | 處理方式 |
|---|---|---|
| 核心 | 穩定幣、各鏈原生幣（BSC 的 WBNB、Solana 的 SOL、Robinhood Chain 的 WETH）、其他股票代幣 | 自動納入比較 |
| 自選報價代幣 | 開發者指定的代幣（例如牛来） | 納入比較，加上標籤 |
| 其他 | 其餘代幣 | 不顯示、不參與比較，但保留資料 |

- **核心級別以合約地址判定**，不用名稱：
  - 穩定幣與各鏈原生幣（含包裝版本，例如 WBNB、WETH、WSOL）由系統內建的「核心報價資產地址表」判定，各鏈分開列出。此表是分類依據，屬於系統內建資料，不是人工設定檔（見 F1），不可移除。
  - 「其他股票代幣」只限資產登記表上的官方代幣（見 F1）；同名的非官方股票代幣歸為「其他」。
- 自選報價代幣以**合約地址**指定，不用名稱（同名仿冒幣很多）。
- 名單改由設定檔管理，修改不需要改程式。
- 第一版只做「核心」級別（見 §3.5）。「自選報價代幣」級別延後；屆時優先做「股票 × 自選報價代幣」的池子（例如 `QQQB/牛来`）。
- 純自選報價代幣池（例如 `牛来/USDT`）另開「自選池」頁面，不混進股票比較；排在「股票 × 自選報價代幣」之後。

> 命名說明：「自選報價代幣」（F5，池子另一邊的資產）與「關注股票」（F6，使用者關注的股票）是兩件不同的事，文件與程式碼中不要混用「自選」一詞。

#### F5 驗收條件（第一版僅核心級別）
- **F5-AC1** 只有另一邊為核心級別資產（穩定幣、各鏈原生幣、其他股票代幣）的池子出現在卡片上。
- **F5-AC2** 「其他」級別的池子不出現在卡片上、不計入交易量，但資料仍保存在資料庫中。
- **F5-AC3** 報價資產的級別依合約地址判定：名稱或代號與核心資產相同、但地址不在核心報價資產地址表上的代幣，歸為「其他」；另一邊為非官方股票代幣（不在資產登記表上）的池子，同樣歸為「其他」。

### F6. 單頁儀表板

公開、唯讀、單一頁面，不需要導覽列。由上到下三個區塊：

**瀏覽與搜尋**
- **分批顯示**：「市場收益排行」先列前 N 檔，點「顯示更多（還有 M 檔）」再載入下一批，全部顯示後按鈕消失，不設上限。每批數量於 UI 規格中訂定。
  - 不採用無限滾動：排行榜的價值集中在前段；無限滾動會讓 Dev's Pick 與計算方法說明永遠滑不到，與原地展開卡片互相干擾，且從 DEX 頁面返回時難以保留位置。
- **搜尋**：一個搜尋框，在瀏覽器端即時篩選已載入的資料，不需要後端。可依**股票代號**（`NVDA` 同時找到 `NVDAB`、`NVDAx`）、**公司名稱**、**合約地址**搜尋。搜尋範圍包含不在排行榜上的股票（情況 C），讓訪客仍能找到並加入關注；以合約地址搜尋可用來核對代幣是否為官方發行。
- **卡片原地展開**，不另開獨立頁面：比較同一檔股票的跨鏈池子是本站核心用途，原地展開可邊看排行邊比較。展開時網址加上該股票的錨點（例如 `#NVDA`），開啟此網址時自動捲到該卡片並展開，以便分享。

**股票卡片**（三個區塊共用同一種卡片）
- 收合時：股票代號、24h 總交易量、**最佳淨收益**、該收益所在的鏈與池子、☆ 按鈕。
- **24h 總交易量只加總卡片展開後列出的池子**（含資料不足、無法計算的池子），不含 V4 / Infinity 池、未啟用 DEX 的池子與「其他」級別報價資產的池子。標籤寫成「收錄池子 24h 交易量」，計算方法說明註明排除範圍。理由：使用者展開卡片自行加總時必須對得上；只取本站採用的數據，不追求涵蓋鏈上全部交易量。
- 展開時：列出該股票各鏈、各發行商、各 DEX 的池子（TVL、交易量、APY、淨收益、手續費損耗比）。同一 DEX 同一交易對的其他費率階梯預設摺疊。
- 展開時的 APY 以 7 天中位數為主，30 天中位數以小字附在旁邊，兩者相差超過一定比例時加上 ↑ / ↓ 箭頭（門檻於計算規格中訂定，只影響顯示），例如 `全區間 APY 25% ↑ 30天 15%`。不另開一欄，避免手機版過擠；不顯示變化幅度，見 §6。收合時不顯示 30 天數字。
- **集中流動性池另以小字顯示「池子平均 APY」**（交易量 × LP 實得費率 ÷ TVL），對應 DEX 頁面與 DefiLlama 上看到的數字，避免使用者以為本站算錯；只作參考，不參與任何計算。附 ⓘ 說明，例如：「池子平均是所有 LP 的平均收益。這個池子的流動性大多集中在現價附近的窄區間，由積極調整區間的做市商賺走大部分手續費；全區間的被動 LP 實際約能拿到 3.1%。」V2 池兩者相同，只顯示一個。範例：

  ```
  PancakeSwap V3 · TSLAB/USDT 0.25%              [前往池子]
  TVL $2.06M   24h 交易量 $1.36M
  全區間 APY 3.1% ↑ 30天 2.5%     池子平均 60.4% ⓘ
  淨收益 +1.3%    損耗比 59%
  ```

- **`≈` 標記只用於含額外已知近似的數字**，目前為回補期間的值（例如 `全區間 APY ≈3.1%`），點擊說明「含回補期間的估算值，系統運行滿 30 天後自動改為實測值」。所有數字本來就只能參考（σ 為歷史估計、無常損失公式為近似），這由免責聲明與計算方法說明處理，不逐一標記；若每個數字都加 `≈`，標記就失去資訊量。
- 每個池子附上**前往該 DEX 池子頁面的連結**（PancakeSwap、Raydium、Orca 等），作為看完數字後的下一步。
- 每個代幣顯示**合約地址**（可複製）與**區塊瀏覽器連結**（BscScan、Solscan、Robinhood Chain 官方文件列的 Blockscout `robinhoodchain.blockscout.com`），方便操作前核對、避開仿冒代幣。
- **最佳淨收益**的定義：通過過濾條件（F2）的池子中，「7 天日 APY 中位數扣掉預估無常損失」後的最高值。**不使用原始 APY 的最高值**，避免小池子或單日暴衝誤導排序。
- **最佳淨收益為負時照實顯示**（紅色），不隱藏、不改成「—」：代表該股票目前所有池子的手續費都不足以補償波動風險。
- **沒有最佳淨收益的股票**：依股票目前的池子分三種情況：

  | 情況 | 例子 | 收合時顯示 | 在「市場收益排行」的位置 |
  |---|---|---|---|
  | A. 至少一個池子可參與排名 | 一般股票 | 最佳淨收益 | 依最佳淨收益排序 |
  | B. 有收錄的池子，但全部屬於排除類狀態 | 新上架只有 4 天資料；只有讀不到 L 的池子；代幣已下架；資料源斷線超過 24 小時 | 「—」加上主要原因（例如「資料僅 4 天」）：先取每個池子的主要狀態再統計，取池子數最多者；數量相同時取狀態表中較前者 | 排在所有 A 之後，彼此依 24h 交易量排序 |
  | C. 沒有任何收錄的池子 | 鏈上沒有池子，或池子全部低於 TVL 下限 | 「目前沒有收錄的池子」 | 不出現；可被搜尋、加入關注 |

  - 斷線時池子仍在登記表上，只是狀態變成「數據過期」，屬於情況 B，卡片不會消失。
  - xStocks 官方清單約 1,184 檔美股代幣，多數預期沒有像樣的池子，情況 C 是常態而非例外。

**其他要求**
- 「我的關注」為空時，顯示提示（例如「點 ☆ 把股票加到這裡」）。
- 「我的關注」存在瀏覽器，不跨裝置同步，清除瀏覽器資料後會消失；這是已知限制。
- Dev's Pick 放在三個區塊的最後，位於頁尾的計算方法說明之前，不干擾其他訪客。頁面由上到下：我的關注 → 市場收益排行 → Dev's Pick → 計算方法說明（頁尾）。
- 每個數字都要附上免責聲明（沿用參考專案的 DYOR 原則）。
- **數據新鮮度分級**（每個池子各自判斷）：未滿 2 小時正常顯示；2 小時以上、24 小時以內為「數據延遲」；超過 24 小時為「數據過期」。顯示方式與是否參與排名見 F2「池子狀態一覽」。

- 整個排程超過 2 小時沒有成功完成時，頁面頂端顯示橫幅：「資料更新中斷，以下為 X 時的數據」。**不整頁屏蔽**：本站沒有操作功能，出事時正是使用者最需要看數據的時候。
- 頁面底部提供**計算方法說明**：淨收益如何計算、哪些池子被過濾及原因、估算的已知限制（不含挖礦獎勵、回補期間 TVL 與集中流動性池的 L 為近似值、波動率取自美股股價而非鏈上代幣價格，未涵蓋週末及流動性差時代幣自身的價格偏離，對流動性差的池子可能低估無常損失）。內容可改寫自參考專案的 `MODEL.md`。
- 計算方法說明另須解釋以下觀念，避免誤讀：
  - **本站評估的是被動 LP，所以數字比 DEX 頁面低**：DEX 頁面顯示的是池子平均，集中流動性池的手續費大多被積極調整區間的做市商拿走；全區間的被動 LP 實際拿到的遠低於帳面。集中流動性會把收益與無常損失同步放大，淨收益為負的池子集中只會虧得更快。
  - **當 LP 是做空波動率**：獲利上限是手續費，股價大漲或大跌都對 LP 不利。單邊流動性（V3 單邊區間）同樣是做空波動率，等同掩護性買權或賣出 put，適合當作「本來就要買賣時的下單方式」，不是收益策略。
  - **排名相近不代表有高低之分**：淨收益是估計值，誤差主要來自 σ（以過去約 3 個月的股價估計，例如 σ = 38% 時估錯 10%，無常損失約變動 0.36 個百分點），以及集中流動性池的流動性分布隨時變動，實際倉位的收益未必與估計一致。淨收益差距在一定範圍內（例如約 0.5 個百分點）的池子應視為同級。介面不逐一標示，理由同 `≈` 標記的原則（見 F6）。
  - **手續費損耗比的含義**：超過 100% 只表示「現在當 LP 不划算」，**不代表**這檔股票適合買進或賣出；損耗比不看價格方向。它也不是永久狀態，交易量上升或波動下降時會改變。此指標對應期權交易中的 Richness 概念，供想深入了解的人查詢。
- 加上不需 cookie 的流量統計（例如 Cloudflare Web Analytics），作為日後是否升級產品的判斷依據。

#### F6 驗收條件

**排行與卡片**
- **F6-AC1** 「市場收益排行」依最佳淨收益由高到低排序；最佳淨收益為可參與排名的池子中，淨收益最高者。
- **F6-AC2** 最佳淨收益為負時，以紅色顯示實際數值，不隱藏、不顯示「—」。
- **F6-AC3** 所有池子都屬於排除類狀態的股票（情況 B），排在所有可排名股票之後，彼此依 24h 交易量排序；收合時顯示「—」與主要原因。主要原因只以每個池子的主要狀態統計（次要狀態不計入），取池子數最多者；數量相同時取狀態表中較前者。例：2 個池子「資料不足」、2 個池子「無法計算」，顯示「無法計算」。
- **F6-AC4** 沒有任何收錄池子的股票（情況 C）不出現在排行榜，但可被搜尋、加入關注，卡片顯示「目前沒有收錄的池子」。
- **F6-AC5** 資料源中斷超過 24 小時，原本有池子的股票卡片仍留在排行榜上（轉為情況 B），不會消失。
- **F6-AC6** 卡片的 24h 交易量等於展開後列出的所有池子 24h 交易量的總和。
- **F6-AC7** 最佳淨收益所在的池子帶有提示類標記時，卡片收合狀態也顯示該標記的圖示。
- **F6-AC8** 集中流動性池同時顯示全區間 APY 與小字的池子平均 APY；V2 池只顯示一個 APY。
- **F6-AC9** 7 天與 30 天中位數相差超過門檻時顯示 ↑ 或 ↓；收合時不顯示 30 天數字。
- **F6-AC10** 每個池子附有前往該 DEX 池子頁面的連結；每個代幣顯示可複製的合約地址，以及對應鏈的區塊瀏覽器連結。

**瀏覽與搜尋**
- **F6-AC11** 排行榜初次只顯示第一批股票；「顯示更多」按鈕顯示剩餘檔數，點擊後載入下一批，全部顯示後按鈕消失。
- **F6-AC12** 搜尋股票代號可找到該股票（例：輸入 `NVDA` 找到包含 `NVDAB`、`NVDAx` 的卡片）；搜尋公司名稱同樣可找到。
- **F6-AC13** 貼上官方合約地址可找到對應的股票；貼上不在登記表上的地址，顯示找不到。
- **F6-AC14** 搜尋結果包含不在排行榜上的股票（情況 C）。
- **F6-AC15** 展開卡片時網址加上該股票的錨點；直接開啟帶錨點的網址時，頁面自動捲到該卡片並展開。

**關注與其他**
- **F6-AC16** 按 ☆ 加入的股票出現在「我的關注」，重新整理頁面後仍在；清單為空時顯示提示。
- **F6-AC17** 加入或移除關注時，瀏覽器不對伺服器送出任何寫入請求。
- **F6-AC18** 整個排程超過 2 小時沒有成功完成時，頁面頂端顯示中斷橫幅，下方數據照常顯示。
- **F6-AC19** 頁面底部的計算方法說明涵蓋本節列出的所有項目（計算方式、過濾原因、已知限制、已排除 V4 / Infinity 池與未啟用的 DEX、交易量的排除範圍，以及四個需解釋的觀念）。

**補充（2026-10-26 審查後新增）**
- **F6-AC20** 展開的卡片列出該股票所有收錄的池子（各鏈、各發行商、各 DEX），每個池子顯示鏈、發行商、DEX、TVL、24h 交易量、全區間 APY、淨收益與手續費損耗比（無法計算者顯示「無法計算」）。
- **F6-AC21** Dev's Pick 是三個區塊中的最後一個，位於頁尾的計算方法說明之前，依設定檔的順序顯示設定檔中的股票與短評；沒有短評的股票只顯示卡片。
- **F6-AC22** 「我的關注」預設依 24h 交易量由高到低排序，可切換成依淨收益排序。
- **F6-AC23** 所有排序（排行榜、我的關注、費率階梯的預設池子）在排序值相同或缺漏時，依固定的次要排序決定順序；相同的資料重複產生，排序結果完全相同（次要排序鍵見計算規格）。

## 9. 未來規劃（不在目前範圍）

**第二版候選**
- **通知提醒**（優先）：關注的股票最佳淨收益超過門檻，或持有的池子淨收益轉負時，透過 Telegram 等管道通知。**由同一台伺服器上的 agent 框架實現**（例如 Hermes Agent），本站不開發通訊軟體模組：agent 讀取本站的資料介面（`latest.json` 與唯讀命令列），再以自己支援的 Telegram、Discord、Slack、LINE 等管道與使用者互動。本站只負責資料介面的穩定；關注清單、持倉等個人資料留在 agent 端，本站仍不碰錢包。agent 預設只能讀取，不能修改本站的資料或設定。
- **淨收益歷史走勢圖**：展開卡片時顯示該池子 30 天的淨收益變化。
- **長期 APY 穩定度指標**：歷史快照累積足夠後，用滾動視窗（例如最近 90 天）或分位數（例如「過去 90 天有 80% 的日子 APY 高於 X」）評估穩定度，不把全部歷史混在一起算，因為池子狀態會隨競爭池、獎勵活動、財報季改變。與「淨收益歷史走勢圖」共用同一份歷史快照，可一起規劃。
- **跨發行商比價**：同一標的不同發行商代幣（如 TSLAB、TSLAx）相對真實股價的溢價/折價。
- **非美股標的**：xStocks 官方清單中倫敦、香港、歐陸掛牌的代幣（例如 `TCENTx`）。需處理非美股的股價來源、交易時段與幣別。
