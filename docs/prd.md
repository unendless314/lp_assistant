## 1. 背景

參考專案 [`bstocks-lp-assistant`](../reference/SOURCE.md) 用期權視角評估代幣化股票 LP 的風險調整收益，數學模型完善，但有三個限制：

1. 只看 BSC 上的 bStock，看不到 Solana 等其他鏈與其他發行商。
2. 無法比較同一檔股票在不同鏈、不同池子的收益。
3. 池子資料依賴 `baw`，必須登入錢包才能運作。

## 2. 目標

做一個**唯讀**的代幣化股票 LP 比較工具：對同一檔美股，列出它在各鏈、各發行商、各費率階梯的 LP 池子，用一致的方法比較風險調整後的收益，並提供資金配比建議。

## 3. 使用者與使用情境

- **定位**：個人工具，公開唯讀。不做帳號、不做登入，任何人都能瀏覽。
- **主要使用者**：開發者本人。
- **其他訪客**：可以瀏覽、在自己的瀏覽器裡建立關注清單。
- **使用情境**：打開網頁，看自己關注的股票目前哪條鏈、哪個池子的淨收益最好；順便看市場上淨收益最高的是哪些股票。
- 若之後確認有流量，再評估是否升級為正式產品（見 §9）。

**與參考專案的定位差異**

| | 參考專案 | 本專案 |
|---|---|---|
| 定位 | Agent 互動工具 | 資料匯集站 |
| 運作方式 | 使用者提問時即時抓取、計算 | 排程定期抓取、計算並儲存 |
| 介面 | Claude 對話、命令列 | 只有網頁 |
| 與錢包的關係 | 讀取持倉、交給錢包執行 | 完全不碰 |

因此只移植參考專案的數學模型與過濾規則，不移植其互動流程。未來需要依使用者輸入計算的功能（資金配比、區間試算），須在瀏覽器端計算或事先算好，因為伺服器只提供靜態檔案。

## 4. 功能需求

### F1. 代幣與池子收錄
- 收錄幣安清單上的 bStock（BSC）與 xStocks（Solana、BSC），以及 Robinhood 官方清單上的股票代幣（Robinhood Chain）。
- **只收錄官方清單上的代幣**（以合約地址比對），第三方發行的同名代幣、槓桿代幣（如 `AAPLx3L`）一律不收錄。
- 以美股標的對齊不同鏈、不同發行商的代幣（`TSLAB`、`TSLAx`、Robinhood 的 `TSLA`）。有 ISIN 時優先用 ISIN 對齊，避免同代號不同股票類別混淆。
- 同一檔股票在同一條鏈上可能有多個發行商，兩者都要列出。
- **資產登記表**：系統自己維護一份已收錄代幣的登記表，網頁一律依登記表呈現股票卡片，不因當下抓不到數據而消失。
  - 官方清單只能**新增**登記，不能刪除。新代幣出現在官方清單即自動收錄，不需人工核准。
  - 代幣從官方清單消失時只改狀態：連續 N 天未出現才標為「官方已下架」（N 由設定檔決定），避免官方 API 單日異常造成誤判。
  - 「官方已下架」的代幣照常顯示池子的 TVL、交易量、原始 APY，加上醒目標籤，**不參與排名**。理由：下架、破產屬於跳空事件，代幣也可能因停止贖回而與股價脫鉤，模型的波動率與無常損失估算不再適用。
  - 人工設定檔只做例外調整（以合約地址排除特定代幣、加註記），系統沒有它也能運作。
  - 每次登記表有變動（新增、消失、恢復），記錄下來供開發者查看。

### F2. 收益與風險評估
- 沿用參考專案的量化方法：Yang-Zhang 波動率、相對波動率（非穩定幣配對）、損益平衡波動率與 Richness 評級、集中流動性區間與存活機率。
- **波動率資料來源：美股股價（yfinance 日 K 線），三條鏈統一**，不使用參考專案的幣安 DEX K 線。
  - 理由：同一檔股票在各鏈的 σ 相同，跨鏈淨收益的差異只反映手續費收益，比較結果不混入資料源差異；幣安 K 線很可能不涵蓋 Robinhood Chain。
  - 非穩定幣配對（股票 / WETH、WBNB、SOL）的報價資產價格同樣取自 yfinance（例如 `ETH-USD`）。相對波動率**只用兩邊都有資料的日子對齊**（即美股交易日），週末缺口為可接受的取捨。
  - 股票代號需轉換成 Yahoo 格式（例如 `BRK.B` → `BRK-B`）。標的沒有公開股價的代幣，標示「無法計算」。
- 沿用參考專案的過濾規則：TVL 下限、異常費率、同標的 APY 離群值。
- **排名用的收益**：每日 APY 的 **7 天中位數**，用中位數排除單日暴衝（例如大單造成的單日高 APY）。中位數代表「典型一天」的收益，比平均更能預估現在投入後可持續的收益；單日大單無法預期，也可能是刻意刷量。
- **30 天中位數**：只用於顯示，與 7 天對照看出收益趨勢，不參與排名（顯示方式見 F6）。歷史資料不足 30 天時顯示「—」，不用不足的資料硬算。
- **7 天與 30 天一律由本系統自行計算**，不使用資料源現成的值（例如 DefiLlama 的 `apyMean30d`）：它只涵蓋 Solana，BSC、Robinhood 仍須自算，混用反而多一條路徑；且其為平均而非中位數、定義無法驗證。資料源的值只用於對照檢查，差距過大時標記異常。
- **APY 穩定度另外標示，不納入排名**：以變異係數（標準差 ÷ 平均）在卡片上標示「收益波動大」，門檻於計算規格中訂定。不做折價：7 天只有 7 個資料點，折價係數沒有理論依據，排名卻會對它很敏感。長期穩定度指標待歷史快照累積後再做，見 §9。
- **跨池比較必須用同一套 APY 算法**，不能直接混用各資料源自己報的 APY。
- **歷史資料不足的池子**：可用的歷史資料少於 7 天時，標示「資料僅 N 天」，**不參與「最佳淨收益」的選取與排名**，但仍列在展開的卡片中。
- **排除 V4 架構的池子（所有鏈）**：Uniswap V4 與 PancakeSwap Infinity（含 CLMM 與 Bin 池）一律不收錄、不顯示、不計算。這類池子可掛載 hook（池子建立者自訂的合約），可能未經審計，且公開資料源無法得知池子掛載了哪個 hook。此規則沿用參考專案的 V4 封鎖原則；除非開發者明確同意，否則不開發 V4 相關功能。計算方法說明中須註明已排除這兩類池子。
- **費率無法取得的池子**（例如動態費率池）：無法用一致的公式估算 APY，標示「無法計算」，不參與排名。
- **數據過期的池子**：距最後一次成功更新超過 24 小時，不參與排名（顯示方式見 F6）。
- **排名只用淨收益，Richness 不作為門檻**：Richness 評級（Rich / Fair / Cheap）只顯示，不過濾任何池子。產品導向是呈現全貌、由使用者自行判斷，不主觀屏蔽。
  - 在全區間無常損失公式下，Richness ≥ 1（Cheap）與淨收益 ≤ 0 在數學上等價，Cheap 池會自然排在最後，不需額外規則。
  - 淨收益與 Richness 回答不同問題：淨收益是「預期賺多少」，Richness 是「波動率估錯時還有多少緩衝」，兩者排序可能相反（例如高 APY 高波動的池子淨收益較高，但安全邊際較小）。

### F3. 比較視圖
- 跨鏈：同一檔股票在各鏈的收益、TVL、交易量。
- 跨發行商：同一檔股票的不同發行商代幣。
- 跨費率階梯：同一 DEX 同一交易對的不同費率池，預設只顯示最佳的一個，可展開查看其他。

### F4. 資金配比建議
- 兩種模式：安全型（依 TVL 深度分配）與進取型（依收益最佳化，考慮自我稀釋）。
- 可用滑桿在兩者之間調整。
- 細節待討論，見 §8。

### F5. 報價資產分級與自選報價代幣
池子依「另一邊的資產」分三級：

| 級別 | 內容 | 處理方式 |
|---|---|---|
| 核心 | 穩定幣、原生幣（WBNB、SOL）、其他股票代幣 | 自動納入比較 |
| 自選報價代幣 | 開發者指定的代幣（例如牛来） | 納入比較，加上標籤 |
| 其他 | 其餘代幣 | 不顯示、不參與比較，但保留資料 |

- 自選報價代幣以**合約地址**指定，不用名稱（同名仿冒幣很多）。
- 名單改由設定檔管理，修改不需要改程式。
- 優先做「股票 × 自選報價代幣」的池子（例如 `QQQB/牛来`）。
- 純自選報價代幣池（例如 `牛来/USDT`）另開「自選池」頁面，不混進股票比較；排在後面的版本。

> 命名說明：「自選報價代幣」（F5，池子另一邊的資產）與「關注股票」（F6，使用者關注的股票）是兩件不同的事，文件與程式碼中不要混用「自選」一詞。

### F6. 單頁儀表板

公開、唯讀、單一頁面，不需要導覽列。由上到下三個區塊：

| 區塊 | 內容 | 預設排序 | 資料存放 |
|---|---|---|---|
| **我的關注** | 訪客用 ☆ 加入的股票 | 24h 交易量（可切換成淨收益） | 訪客自己的瀏覽器 |
| **市場收益排行** | 全部股票 | 最佳淨收益 | 伺服器產生的資料 |
| **Dev's Pick** | 開發者挑選的股票，可附一句短評 | 開發者自訂 | 伺服器上的設定檔 |

**股票卡片**（三個區塊共用同一種卡片）
- 收合時：股票代號、24h 總交易量、**最佳淨收益**、該收益所在的鏈與池子、☆ 按鈕。
- 展開時：列出該股票各鏈、各發行商、各 DEX 的池子（TVL、交易量、原始 APY、淨收益、Richness 評級）。同一 DEX 同一交易對的其他費率階梯預設摺疊。
- 展開時的 APY 以 7 天中位數為主，30 天中位數以小字附在旁邊，兩者相差超過一定比例時加上 ↑ / ↓ 箭頭（門檻於計算規格中訂定，只影響顯示），例如 `APY 25% ↑ 30天 15%`。不另開一欄，避免手機版過擠；不顯示變化幅度，見 §6。收合時不顯示 30 天數字。
- 每個池子附上**前往該 DEX 池子頁面的連結**（PancakeSwap、Raydium、Orca 等），作為看完數字後的下一步。
- 每個代幣顯示**合約地址**（可複製）與**區塊瀏覽器連結**（BscScan、Solscan），方便操作前核對、避開仿冒代幣。
- **最佳淨收益**的定義：通過過濾條件（F2）的池子中，「7 天日 APY 中位數扣掉預估無常損失」後的最高值。**不使用原始 APY 的最高值**，避免小池子或單日暴衝誤導排序。
- **最佳淨收益為負時照實顯示**（紅色），不隱藏、不改成「—」：代表該股票目前所有池子的手續費都不足以補償波動風險。

**其他要求**
- 「我的關注」為空時，顯示提示（例如「點 ☆ 把股票加到這裡」）。
- 「我的關注」存在瀏覽器，不跨裝置同步，清除瀏覽器資料後會消失；這是已知限制。
- Dev's Pick 放在最下方，不干擾其他訪客。
- 每個數字都要附上免責聲明（沿用參考專案的 DYOR 原則）。
- **數據新鮮度分級**（每個池子各自判斷）：

  | 距最後成功更新 | 顯示 | 參與排名 |
  |---|---|---|
  | 2 小時內 | 正常 | 是 |
  | 2～24 小時 | 黃色標示「數據 N 小時前」 | 是 |
  | 超過 24 小時 | 灰掉，標示「數據過期」 | 否 |

- 整個排程超過 2 小時沒有成功完成時，頁面頂端顯示橫幅：「資料更新中斷，以下為 X 時的數據」。**不整頁屏蔽**：本站沒有操作功能，出事時正是使用者最需要看數據的時候。
- 頁面底部提供**計算方法說明**：淨收益如何計算、哪些池子被過濾及原因、估算的已知限制（CLMM 為粗估、不含挖礦獎勵、回補期間 TVL 為近似值、波動率取自美股股價而非鏈上代幣價格，未涵蓋週末及流動性差時代幣自身的價格偏離，對流動性差的池子可能低估無常損失）。內容可改寫自參考專案的 `MODEL.md`。
- 計算方法說明另須解釋以下觀念，避免誤讀：
  - **當 LP 是做空波動率**：獲利上限是手續費，股價大漲或大跌都對 LP 不利。單邊流動性（V3 單邊區間）同樣是做空波動率，等同掩護性買權或賣出 put，適合當作「本來就要買賣時的下單方式」，不是收益策略。
  - **Richness 的含義**：Cheap 只表示「現在當 LP 不划算」，**不代表**這檔股票適合買進或賣出；Richness 不看價格方向。Cheap 也不是永久標籤，交易量上升或波動下降時會改變。
- 加上不需 cookie 的流量統計（例如 Cloudflare Web Analytics），作為日後是否升級產品的判斷依據。

## 5. 非功能需求

| 項目 | 要求 |
|---|---|
| 安全 | 伺服器不存放任何私鑰、助記詞或錢包登入憑證；沒有任何交易功能 |
| 可用性 | 24 小時在線，部署於雲端 VPS；資料流程中斷後必須能**自動恢復**，不得依賴需人工介入才能恢復的元件（例如需手動登入的 session）。人工設定只用於例外調整，系統沒有它也能運作 |
| 資料新鮮度 | 每 15~60 分鐘更新一次；任何資料來源中斷時，網頁沿用最後一次成功的資料照常運作，並依 F6 的新鮮度分級標示 |
| 資料留存 | 池子快照為無法重建的資產（歷史 TVL 只有本系統有），永久保存並定期備份。最近 90 天保留原始頻率（每次更新一筆）；更早的資料彙整成每日一筆（TVL 平均、最高、最低，及當日交易量）後永久保存 |
| 外部請求 | 訪客瀏覽不會直接觸發外部 API 請求 |
| 股價資料 | 每天抓取一次，日 K 線存入資料庫，每次只補最近幾天；抓取失敗時沿用上次算出的 σ，超過 7 天未更新才標示「無法計算」；鎖定 yfinance 版本；股價抓取集中於單一模組，長期失效時可替換資料源（例如 Stooq） |
| 伺服器寫入 | 網頁沒有任何寫入伺服器的功能；訪客的操作（☆ 關注）只存在訪客的瀏覽器 |
| 裝置 | 支援手機與桌機（響應式排版），手機上不需要橫向捲動 |
| 語言 | 第一版只做繁體中文。**預留多語系銜接點**：介面文字一律集中在語系檔、不寫死在元件裡；數字、金額、日期依語系格式化，第二版加英文時只需新增語系檔 |
| 可維護性 | 改計算公式、換資料源、加新鏈，彼此不互相影響 |
| 部署 | 使用者既有的 VPS + 網域，前面加 Cloudflare |
| 授權 | 移植自參考專案的程式碼保留 MIT 版權聲明 |

## 6. 已確認的決策

| 日期 | 決策 | 理由 |
